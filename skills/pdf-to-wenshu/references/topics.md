# 方法专题工作流（`Topics/` · 文枢「方法库」）

方法专题 = **按方法组织**的知识文档，不逐篇复述论文：主干（流程/方程/数值实现/验证）为该方法所有研究共享，变体分支记录各研究在主干哪一环节做了修改。

放 `<VAULT>/Topics/<主题>/<文档名>.md`，frontmatter：
- `noteType: topic`
- `docType: 方法专题`
- `domain: <方法名>`——**方法是方法、领域是领域，别把方法名当子领域塞进 `Papers/` 分类**（历史教训：`泥沙输运/CFD-DEM` 属于层级颠倒）
- `papers:` 覆盖账本（文枢「该主题论文」按它筛选）
- `updated`

渲染契约同 `wenshu-pro/docs/content-contract.md`；**H1 后禁止跟 blockquote**（Web 会渲染成「说明」卡片把下文整块吞进去）。

## 三段式生成（防偷懒，顺序不可换）

### 1. 采证（禁止写正文）

按 SKILL.md「检索协议」找齐库内相关论文，逐篇读 `notes.md`，为每篇提取「方法配置清单」：耦合方式 / 关键子模型（曳力、湍流、接触模型…）/ 时间步 / 耦合频率 / 软件 / 验证手段——有则填**具体数值**，无则明确写「未提及」。

本步产出是事实表格，不是文章；清单空 = 没读论文，立刻暴露。

### 2. 定框架

先写 H2 骨架和每节验收条件再动笔。方法专题必备 9 节（`topic_lint` 强制）：

**方法定义 / 适用范围 / 计算流程总览 / 控制方程 / 数值实现要点 / 方法变体与扩展 / 库内论文方法配置对照 / 验证与标定 / 待补文献与扩展方向**

硬性要求：
- **方法定义**先给正式定义再谈边界。
- **控制方程**必须 `$$` LaTeX + 逐符号定义，不接受纯文字。
- **数值实现要点**判据公式先行——时间步/网格等数值约束先写判据公式（如 Rayleigh 时间步 $\Delta t_R$、CFL 条件），再给工程取法与库内取值。**禁止只报库内数值不报判据**（数值是实例、判据才可迁移；`topic_lint` E9 强制该节含 `$$`）。
- **配置对照**一篇一行、数值抄第 1 步清单。
- **每个变体**统一按四段组织：动机（基准方法在该场景的局限）/ 技术要点（对基准框架改了什么）/ 适用性与局限（以文献为据，写不出就省略，禁止臆造「代价」）/ 库内应用。

文体要求：
- 全文用学术措辞，禁止「一句话定位」「变体地图」「解决什么/改哪一环」这类口语标题与口语字段名。
- **书面语体**：正文为学术书面语，禁口语比喻与俗语（「打折版/地盘/赛道/一坨/打架/万事大吉/跑不动」级词汇，`topic_lint` 黑名单会拦截），避免第二人称；数学表达一律 LaTeX。

**配图**：方法专题不是纯文字——应从库内论文引 2–4 张关键图（方法流程示意、颗粒/网格示意、验证对照图），写法 `![[<pid>_pageX_figY.png|700]]` + 下一段 `**图 N：** 说明（引自 [[pid]] 图 M）`。图名从该论文的 `<pid>.images.md` 抄，Web 端按图名的 pid 前缀自动定位所属论文图片目录（跨论文引图无需拷文件），`topic_lint` 校验文件真实存在。不搬论文的结果图（结果属于论文详情页）。

### 3. 填充 + 机器验收

对着验收条件逐节写，写完跑：
```bash
python "<SCRIPTS>/topic_lint.py" --vault "<VAULT>"
```
检查：frontmatter 必填、`papers` 账本 pid 真实入库、H1 后无 blockquote、`$$` 配对、9 节齐全、控制方程节有公式、账本每篇论文都进配置对照表；警告：空话黑名单、正文互链论文漏记账本。

**有 E 不得宣称完成**；收尾照常 `sync-vault.py`（含 web_lint）。

## 增量生长（新论文入库后）

若涉及已有方法专题，只在生长区追加——配置对照加一行、有新变体加一条、`papers:` 账本加一笔、待补文献划掉已入库项——然后 `topic_lint` + `sync-vault`。

**不重写主干**；子方向内容多到撑爆一节时才拆子专题。

**综述等其他 docType** 暂只做通用检查（frontmatter/账本/格式/空话），章节骨架定型后再往 `topic_lint` 加规则。
