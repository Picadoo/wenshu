# 内容角色 Prompt 模板

主代理在步骤⑥安排内容角色时读本文件。A/D 是正常路径的 Luna Max 翻译与英文校订档；C 是必须登记理由才可启用的异常兜底；B 是主代理分析档。
同一篇论文内 A 与 B 可并行；D 等 A 完成后再做。跨篇并行必须走 §0 的任务板，不要在 prompt 里写死「你做第几篇」。

**执行角色固定**：宿主支持模型选择时，A/C/D 使用 `gpt-5.6-luna`、`reasoning_effort=max`；B 由主代理亲自完成。若 Luna Max 不可用，使用当前可用模型但不得把 B 档分析下放。全程 UTF-8。

主代理围绕内容角色记录 job 分段时间：派发前运行 `ingest_stage.py --job <job> start --stage lunaA|mainAnalysis|lunaD`，角色完成后运行对应的 `finish`。英文确定性草稿阶段记作 `prepEnglish`。不要凭体感猜“十分钟花在哪”。

## 子代理启动方式（A/D/C 必须遵守）

本文件是**主代理的规则来源，不是要整份塞给子代理的 prompt**。真实会话审计发现，子代理完整读取 `SKILL.md`、本文件和 `content-contract.md` 后又因输出截断分段重读，D 档只改一行也因此花了两分多钟。

主代理先运行：

```bash
python "<SKILL_DIR>/scripts/build_agent_brief.py" --job "<job>" --role A
python "<SKILL_DIR>/scripts/build_agent_brief.py" --job "<job>" --role D --draft "<draft>"
```

把生成的自包含文本原样交给 `gpt-5.6-luna` / `max`，并使用 `fork_turns: none`。不要在任务里要求“使用 pdf-to-wenshu 技能”或再次读取整套规则；子任务是已准备好的局部文件编辑，不负责入库编排。A 每个全文区间只读一次，D 只读 TODO/lint 指向的局部。子代理 final 会自动返回父代理，不要让它探测或调用额外消息工具。

清洁全文约 1000 行以上、至少 3 个 Luna 槽位且用户优先墙钟时，可由主代理运行 `luna_a_parts.py prepare`，并发发送 manifest 中的章节分片任务；其他情况仍用单 A。分片代理只写独立 `.zh.md`，读完直接一次写入，不在写前 `Test-Path`，写后不重读、不统计、不自验。父代理统一运行 `luna_a_parts.py merge` 做图表去重、标题规范化和完整性门禁。并行会增加总 agent 时间，因此不要为了“看起来并行”默认启用。

## 0. 并行安全：写权归属与自验（跨篇并行时必读）

多子代理同时干活，唯一会出事的地方是**两个代理写同一个文件**。按下表分权，就不需要任何额外协调：

| 角色 | 只能写 | 一律不许碰 |
| --- | --- | --- |
| Luna Max 子代理 | 自己认领那篇 pid 的 `content/<pid>.正文.md`、`.正文.en.md`，或暂存区对应草稿 | `.notes.md`、`terms.json`、索引 `<pid>.md`；别的 pid；全部共享产物；`wenshu-pro/`；会话上下文 |
| 主代理 | `content/<pid>.notes.md`、job 指定的 `terms.json`、索引 `<pid>.md`；共享文件；串行跑 update_terms / build_index / build_bib / sync-vault | 不在 Luna 工作期间重写同一篇正文文件 |

**跨篇返工每做完一篇立刻自验**（两条都必须通过）；单篇首次入库的 A/B 并行阶段由主代理等所有角色就绪后统一跑，因为整篇质检会同时检查 notes 与 index：

```bash
python "<SKILL_DIR>/scripts/lint_cluster.py" --vault "<VAULT>" --paper "<pid>"
python "<WENSHU>/scripts/web_lint.py"        --vault "<VAULT>" --paper "<pid>" --fail-on-warnings
```

⚠️ `lint_cluster` **不要加 `--report`**：那会重写全库共享的 `90_系统/_质检报告.md`，并行时互相覆盖。新论文的单篇 Web 验收采用严格模式，任何警告都必须在入库前处理。
`--paper` 只缩小「检查哪些集群」，悬空链接仍按全库 pid 表判定，不会因为缩小范围而误报。

**任务板（跨篇并行的调度骨架）**：主代理建板，子代理自己认领——子代理中途死掉，租约到期后活会自动回收给别人，不会静默丢篇。

```bash
# 主代理：建板（items 一行一个 pid）
python "<SKILL_DIR>/scripts/workboard.py" --vault "<VAULT>" init --task en-revise --items-file "<清单>"
# 子代理：认领 → 干活 → 自验 → 每篇立刻回报
python "<SKILL_DIR>/scripts/workboard.py" --vault "<VAULT>" claim  --task en-revise --agent "<自己的名字>" --n 3
python "<SKILL_DIR>/scripts/workboard.py" --vault "<VAULT>" report --task en-revise --agent "<名字>" --item "<pid>" --status done
# 子代理：提前收工，把没做完的还回去（别直接消失）
python "<SKILL_DIR>/scripts/workboard.py" --vault "<VAULT>" release --task en-revise --agent "<名字>"
# 主代理：随时看全局
python "<SKILL_DIR>/scripts/workboard.py" --vault "<VAULT>" status --task en-revise
```

`claim` / `report` / `release` 各打印一行 JSON，直接解析 `assigned` 字段即可。认领是原子的，
多个子代理同时喊也不会拿到同一篇（已用 8 进程并发压测，零重复派发）。

## 内容角色共享的约束

- **全文已缓存在 `content/<pid>.txt`，优先读它**（省去重抽 PDF）。翻译/笔记一律以它为唯一主要来源直接写；只有当某个公式在 txt 里明显乱了，才去看**对应那一两页**的渲染图核对。**绝不逐页通读所有页面图**——又慢又会触发流超时，曾因此卡死一小时、子代理废掉。
- **表格不要从 txt 里重建**：dump 会把表格打散成一列一列的碎字符，表体数字整段丢失，拿它拼表纯属重造轮子还容易错。表已经确定性抽在 `content/<pid>.tables.md`（英文原表 + 表号 + 页码 + 题注 + 质量标记），直接取。
- 写文件 `encoding='utf-8'`。图片 `![[<pid>_pageX_figY.png|700]]`。
- **图号只准用 job JSON 的 `figures[]`（filename+caption）**，禁止编造 pageX_figY。先读 `<imageIndexPath>` 确认有哪些图，只内嵌真实存在的文件名。
- **只给已入库的笔记/术语加 `[[ ]]`**，未入库论文/概念写纯文本（悬空链接 Web 降级纯文本+告警）。
- 若该 PDF 的 Read 打不开（见 SKILL.md「Read 误报加密」）：别 Read 那个 PDF，公式/表格改读主代理预渲染的整页 PNG，路径由主代理在 prompt 里给。

**文枢渲染器的坑**：表格/列表前必须空一行、用「：」引出（别用行尾「——」顶着表格，否则表格被并进段落不渲染）；表格单元格里的不等号写 `\lt` / `\gt`，别用裸 `<` / `>`（会被当 HTML 转义、崩掉整张表）；公式一律 `$...$` / `$$...$$`。

## A. Luna Max 翻译档 → `<pid>.正文.md`

```
把译文写进正文文件 `content/<pid>.正文.md`（路径用 generate_cluster 返回的 `notes.article`）的 <!--ARTICLE-->…<!--/ARTICLE--> 之间（替换占位、保留标记）：

- 逐节全文中译（按论文真实章节）。**参考文献（References）一节不翻译、不手写、不概括**——收尾由 build_refs.py 自动生成带 DOI 链接与库内互链的「## 参考文献」；正文里的引用记号 [N] / (Author, Year) 原样保留（[N] 会被脚本改成可点击跳转；网页显示作者+年份，不是数字上标）。

- **题名块（H1 之后、`## 亮点` 之前）严格三行，禁止自由发挥**——使用 `Example2024 示例论文.正文.md` 这样的统一格式：
    第 1 行 `**作者A、作者B、作者C**`（裸加粗段，全名顿号分隔，**禁止 `^{1,2}` 上标号**）
    第 2 行 单位（裸文本段，多单位用 `；` 分隔）
    第 3 行 期刊卷期页（裸文本或斜体）
  **这三行一律不准写成引用块 `>`**，也不准套 `**文献信息**：`／`**论文信息**：`／`> 期刊：` 之类自造前缀。
  ⚠️ 原因：`## 亮点` 之前只要出现任何非「说明」的引用块，文枢渲染器会把它到下一个说明块之间的**整段正文卷进说明卡片**。**H1 之后紧跟 blockquote 同样禁止。**

- **章节编号一律无尾点**：`## 1 引言` / `### 2.1 控制方程`，**禁止 `## 1. 引言`、`### 2.1. …`**（基准篇即无点；`fix_article` 会自动去点，源头别写错）。英文正文侧相反，保留 `## 1. Introduction`。

- **前置块译名必须对齐约定，禁止自造**：
    Key Points / Highlights → `## 亮点`（**禁止写成「要点」**）
    ↳ **中文正文的 `## 亮点` 是文枢契约里的固定前置块，原刊没印也必须有**——此时从摘要提炼 3–5 条。
      提炼只允许发生在**中文侧**；英文正文那边原刊没有就一条都不许写（见下方 D 代理条款）。
    Abstract → `## 摘要`
    Keywords / Index Terms → `**关键词：** a；b；c`（中文正文里是摘要末尾的**加粗行、不单独成节**）
    Plain Language Summary / 通俗摘要 → **不单独成节**（禁止「通俗摘要」；内容已由正式摘要覆盖则直接丢掉）
    图形摘要 → 图后一行 `**图形摘要。** …`（`**` 后留空格），不要另开标题

- 图片原位忠实内嵌 `![[<pid>_pageX_figY.png|700]]`，图片行后**紧跟一段非空**中文图注 `**图 N：** 说明`（收尾 `**` 后必须留一个空格，否则 CommonMark 下加粗失效星号裸奔；优先用 <imageIndexPath> 的图注）。**严禁只写 `**图 N：**` 空标签**：索引缺图注时回 txt 或对应页找原文图注再翻译；仍找不到就向主代理报告，不得用空标签伪装完成。**只嵌图幅本身**：不要整页截图；多面板复合图保持一张整图，不要拆碎片。

- 关键公式转 LaTeX（$..$ / $$..$$）；过于复杂的留图片兜底。

- **表格别手搓：先读 `content/<pid>.tables.md`**（入库时由 `extract_tables.py` 从 PDF 版面确定性抽出的**英文原表**，带表号/页码/题注）。数字与语言无关——**表体照搬，只把表头与行标签译成中文**，一个数都不要重敲。标了「需人工核对」的表说明版面有合并单元格，照 PDF 核对行标签落位；正文提到却没抽到的表才手搓。dump 里那串一行一个词的表体碎片直接忽略，别拿它拼表。

- **重点公式必加「说明」callout**：控制方程／核心指标／模型公式等**重点**公式（挑 3–6 个，不必每条），紧接其 `$$…$$` 块下一行插：
    `> **【说明】** 式 (N) 是…（一句话算什么）；$符号$ 为…；$符号$ 为…（逐项解释主要符号物理含义）；一句直觉／为什么这么算。`
  **公式号一律写 `式 (N)` 圆括号，禁止写 `式[N]` 方括号**（`[N]` 会被 build_refs --inline 当成引用序号，链成跳到第 N 篇参考文献的死链；脚本侧虽已加护栏，源头也别写错）。说明块**整块每行都要带 `>`**，写成一段、别跨出引用块；忠于上下文不臆造，符号用行内 `$..$`，callout 内 `<`/`>` 写 `\lt`/`\gt`。

- 忠实翻译；小白模式下专业名词首次出现可加（中文直译），不改原意。
- **H1 只写译名，禁止加「（中文翻译）」「（方法原理精讲）」**（web_lint 当错误）。
- **中文母语论文（detectedSourceLanguage==zh）：不翻译、也不改写成方法精讲**——按原文真实章节（摘要/关键词/引言/方法/结果/讨论/结语）忠实排进正文；H1 只写原题；文内 `[N]` 原样保留；重点公式仍可加「说明」callout。
```

## B. 主代理分析档 → `<pid>.notes.md` + `terms.json` + `<pid>.md`

```
读 content/<pid>.txt。<pid>.notes.md：🎓 学习卡(带标记)在上、🔬 深度分析 + ✍️ 写作逻辑(占位标题)在下。

1) 学习卡：<!--KEYPOINTS--> 填 5-7 条大白话要点；<!--QA--> 填问答（Q1 固定=科学问题，再 6-9 个）。
   **不要动 <!--TERMS_START/END--> 表**（脚本填）。保留所有标记。

2) 深度分析 + ✍️写作逻辑：替换各标题下占位——
   研究问题 / 方法概述(核心方法+关键公式 LaTeX+架构+创新) /
   实验结果(数据集·设置·关键结果表**取自 content/<pid>.tables.md**) / 深度分析(价值·优势·局限·场景) /
   与相关论文对比 / 技术路线定位 / 未来工作 / 我的综合评价(总分+5 分项)；
   ✍️写作逻辑(论证骨架 / 谋篇布局 / 值得模仿的写法)。只插关键图。

   **「与相关论文对比」「技术路线定位」两节写之前，先整篇 Read `90_系统/_检索速览.md`**
   （全库每篇一行：题｜一句话｜主题｜评分｜→路径，一次读完 ≈9k token，**只读不写**）。
   这两节必须点名库内**真实存在**的论文并加 `[[pid]]` 互链——同赛道的、被本文当基线的、
   方法同源的，各挑几篇讲清"谁解决了什么、本文补了哪一块"。速览里找不到同题材的就
   如实写"库内暂无同类工作"，**不许泛泛而谈"与传统方法相比"，也不许编造论文**。
   ⚠️ 只给速览里确实有的 pid 加 `[[ ]]`，写错的会被 delink_unresolved 降级成纯文本并告警。

3) 写 terms.json 到指定路径：本文重要术语数组，每个
   {term, zhName, fullName, type, domain, definition, context}
   - term：稳定规范名，优先缩写。同一概念用一致 term 以便跨论文查重；用缩写或标准英文名
     （如 SCS-CN method / index of connectivity），别用口语描述。**即使是中文论文，term 也用
     标准英文名/缩写、中文放 zhName**，让术语笔记标题统一成「英文（中文）」并利于查重；
     确实没有通用英文名的才用中文打头。
   - type：方法/模型/指标/算法/物理量/概念/数据集
   - domain：可留空——update_terms 入库时会按「用它的论文的文件夹领域」自动规整。
   - definition：通用释义，写给没读过本文的读者。**写成连贯专业段落，约 3–6 句**，像词条而
     不像填空。要覆盖通行定义、计算或核心机理（指标/方法/模型给出通用公式或步骤）、取值含义、
     以及跟谁易混，但必须连成文章。**禁止** ①②③④ 编号清单，**禁止**每句以「它是」「直觉上」
     起头，**禁止**只把中文名再抄一遍。忠于学界通义、不臆造、不写本文专属数字。
   - context：本文用法。

   **terms.json 必须是合法 JSON**：中文值里别夹裸 ASCII 双引号，要用「」/"" 或写成 \"。
   公式/符号在 definition、context 里用 `$...$` 行内 LaTeX，但 JSON 里每个反斜杠要双写——
   想得到 `$\sqrt{A}$` 就写 `$\\sqrt{A}$`、想得到 `$\varepsilon^{-\beta}$` 写
   `$\\varepsilon^{-\\beta}$`，脚本 json.load 后自动还原。别写纯文本数学（sqrt、epsilon、
   x^2、希腊字母拼成英文单词）。

4) **自己回填索引 `<pid>.md`**（与 notes 同一篇，路径 = 集群目录下与 content/ 平级的 `<pid>.md`）。
   这三块数据只有你手上有，别指望主代理转手——转手漏填会让详情页顶部卡片一直显示
   「待分析子代理填充」，而 lint 查不出来（它只查文件在不在）。四处一起改：
   - `<!--SCI_Q-->…<!--/SCI_Q-->` 之间填科学问题一句话（**保留标记本身**，只换中间的占位文字）
   - `<!--TLDR-->…<!--/TLDR-->` 之间填 ≤40 字的一句话总结
   - `<!--SCORE-->…<!--/SCORE-->` 之间填 `X.X/10`
   - frontmatter：`status: skeleton` → `analyzed`；`quality_score: "[SCORE]/10"` → 真实分数；
     `tags:` 追加每个主题词一条 `主题/<词>`
   **只动这几处**，别重排 frontmatter 其它字段、别动 `## 文献卡` 里的元数据。

5) 最后把以下 JSON 写入本次执行摘要，供严格验收核对已回填内容：
   {"sciQuestion":"一句话","tldr":"<=40字","score":"X.X/10",
    "topics":["3-6个中文主题词，优先取论文作者关键词(Keywords)译成简洁中文（无空格无英文，
              如 滑坡/泥沙连通性/CFD-DEM/受力闭合），没印关键词就据标题+领域提炼"]}

小白模式：要点/问答大白话、术语逐符号、公式翻成人话。
```

> **不要生成概念卡 `cards.md`**——闪卡已随 Obsidian 一起移除（2026-08）。集群里出现 `<pid>.cards.md` 是 lint_cluster 错误；`sync-vault.py` 也已不再搬运和渲染它。

## C. Luna Max 英文重排档 → `<pid>.正文.en.md`（仅英文源论文，脚本失效时兜底）

> **先看有没有草稿**：`scripts/prep_article_en.py` 能把这活的机械部分（切页、去页眉页脚、软连字符拼词、
> 硬折行接段、认章节、图文配对、题名块用 index 元数据重建、**注入英文原表、按公式号搬中文正文的 LaTeX**）
> 确定性做掉。**正常入库一律走 D 档**——A 档译完中文正文后跑一次脚本即可出草稿；
> C 档只在没跑脚本、或脚本对这本期刊版式完全失效时用。

> **硬门禁**：job 的 `englishWorkflow.cFallbackReason` 为空时禁止派 C。主代理必须先运行
> `python "<SKILL_DIR>/scripts/ingest_stage.py" --job "<job>" allow-c-fallback --reason "<具体失效证据>"`。
> 合法理由是解析器崩溃、无分页标记导致结构不可恢复、双栏读取顺序整体不可用；“还有 TODO/警告”不是理由，应交给 D 档局部修补。C 不得与 A 并行。

> 背景：`content/<pid>.txt` 是 PDF 机器 dump——断行断词、页眉页脚混入、图表位置丢失，直接给人读体验极差。本子代理**不翻译**，只把 dump「修复」成结构化 Markdown。这是文枢「英文正文」tab 的数据源，**用户在这个 tab 里双击单词记生词**，所以正文必须干净、结构化。产出要求与中文正文同级。

